## 6. Running the browser check here (Playwright on Alpine)

The e2e suite **passes 22/22** in this sandbox, and the UI fixes in this session were verified in
a real browser, not just jsdom. Getting there needs one non-obvious step:

```bash
apk add --no-cache chromium            # Alpine's build; ~835MB
mkdir -p /opt/pw-browsers && ln -sf /usr/bin/chromium /opt/pw-browsers/chromium
cd frontend && PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers npx playwright test
```

**`npx playwright install chromium` does not work here.** Playwright ships a glibc-linked build;
this image is Alpine/musl, so it dies at spawn with a misleading `ENOENT` — the real cause is
`__memset_chk: symbol not found` and friends. Confirm with `ldd <headless_shell>` before
concluding the download failed. The `PLAYWRIGHT_BROWSERS_PATH` route is not a workaround, it is
the mechanism `frontend/playwright.config.js` was already written for (see the comment at the top
of that file: pre-installed browser at a fixed path, `executablePath` left undefined on CI).

The suite needs **no backend** — `e2e/responsive.spec.js` intercepts every `/api/*` call. The
`/api/events` proxy errors in its output are expected noise (nothing is listening on :8000) and
the tests still pass.

  the `approved` label. Scoped in both `GUARDRAILS.md` ("Approval is human-only" now opens with
